## medium: JavaScript files are included but not type-checked, creating a silent quality gap

id: fnd_sig-feat-config-0c1c23856a-fe52f_2fe476f8b8
category: build-release
confidence: high
triage: risk
status: open
feature: Project config tsconfig.json (feat_config_0c1c23856a)

evidence:
- tsconfig.json:6 (compilerOptions.allowJs)
- tsconfig.json:1-33

With `allowJs: true`, `.js` files participate in the program, but without `checkJs: true` they are not type-checked. This creates an inconsistent contract where TypeScript files are strict but JavaScript can carry unchecked API/shape errors into runtime and releases.

recommendation:
Either disable JavaScript ingestion (`allowJs: false`) or enforce checking for JS (`checkJs: true`). If migration is in progress, scope JS inclusion narrowly and enable `checkJs` per folder via layered tsconfig files.

test analysis:
No tests were provided for this feature, and this is a compile-time configuration gap that runtime tests may not deterministically detect.

suggested regression test:
Add a CI typecheck step (`tsc --noEmit`) with a fixture `.js` file containing an obvious type misuse; verify the build fails when `checkJs` is enabled (or verify `.js` is excluded when `allowJs` is disabled).

minimum fix scope:
tsconfig.json

## high: Platform-specific Darwin ARM64 binaries are declared as direct devDependencies

id: fnd_sig-feat-config-7528cb5b98-628fb_2e9670a2b1
category: build-release
confidence: high
triage: risk
status: open
feature: Project config package.json (feat_config_7528cb5b98)

evidence:
- package.json:32 (devDependencies)
- package.json:40 (devDependencies)

These packages are OS/CPU-specific binary builds. Declaring them as first-class devDependencies makes install/build behavior host-dependent and can fail in Linux/Windows CI or non-ARM64 machines with unsupported platform errors.

recommendation:
Remove direct platform-targeted binary packages from devDependencies and rely on cross-platform parent packages/transitive optional dependencies instead.

test analysis:
No install-matrix or CI validation is included in the provided evidence, so cross-platform dependency resolution failures would not be caught by tests here.

suggested regression test:
Add CI jobs that run dependency installation and build on at least linux-x64 and darwin-arm64.

minimum fix scope:
package.json devDependencies
